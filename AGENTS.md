# AGENTS.md

Правила для агентов, которые вносят изменения в этот репозиторий. Правила использования скилла по
назначению (ответы на вопросы о представлениях ЗУП) — в `SKILL.md`, здесь — только про работу с
кодом и документами репозитория.

## Что где лежит

| Путь | Происхождение | Правка |
|---|---|---|
| `SKILL.md`, `README.md`, `AGENTS.md`, `LICENSE` | вручную | да |
| `references/механизм-представлений.md`, `references/программный-интерфейс.md` | вручную, по README обработки SharedQueryDesignerHRM и коду конфигурации ЗУП | да, при изменениях в документации обработки или в программном интерфейсе конфигурации |
| `references/index.md`, `references/<ВерсияЗУП>/**/*.md` | генерируются `scripts/build_references.py` | **нет** — только через пересборку |
| `data/<ВерсияЗУП>/**/*.json` | выгрузка обработки, `scripts/export_sharedquery.py` | **нет** — только заменой выгрузки целиком |
| `scripts/*.py` | вручную | да |
| `.github/workflows/build.yml` | вручную | да |

## Обязательные правила

- **Никаких упоминаний ИИ-ассистентов и ботов.** Ни в коде, ни в документах, ни в сообщениях
  коммитов, ни в описаниях pull request не должно быть названий ИИ-инструментов (Claude, ChatGPT,
  Copilot и т. п.), строк вида «Generated with …», трейлеров `Co-Authored-By` с ботами и
  подобного. Авторство коммитов — только человек.
- **Генерируемые файлы не редактируются руками.** После любой правки `data/` или `scripts/`
  выполняется `python scripts/build_references.py`; результат в `references/` коммитится вместе с
  изменениями, которые его вызвали. CI делает то же самое и упадёт, если выгрузка невалидна.
- **Содержимое карточек и индекса берётся только из выгрузки.** Репозиторий не ведёт собственных
  описаний полей и параметров представлений; если в карточке чего-то не хватает — это правится в
  обработке SharedQueryDesignerHRM и новой выгрузкой, а не здесь. Ручные документы (`SKILL.md`,
  `references/механизм-представлений.md`, `references/программный-интерфейс.md`) при этом
  **должны** содержать то, чего выгрузка дать не может: ограничения выгрузки, формы программного
  интерфейса, которых нет в шаблонах, соответствие «функция → представление», «похожие, но другие»
  функции. Такие сведения помечаются версией ЗУП, по коду которой они проверены, и не дублируют
  состав полей и параметров из карточек.
- **Терминология.** Предметные термины пишутся по-русски, как в конфигурации 1С: «представление»,
  «фильтр», «отбор», «программный интерфейс», имена представлений и подсистем — без перевода и
  транслитерации. В английских идентификаторах, именах файлов и скриптов «представление»
  передаётся как `sharedquery` (как в связанном проекте SharedQueryDesignerHRM) — **не**
  `presentation`, `view` или `representation`.
- **Язык.** Документация, комментарии в коде, сообщения в консоли и сообщения коммитов — на
  русском. Формат сообщения коммита: `<тип>: <что сделано>` (например
  `chore: пересобрать references из data/`, `docs: уточнить правила отборов`).
- **Скрипты.** Python 3.10+, только стандартная библиотека — новые зависимости не добавляются.
  Скрипты должны работать и на Windows (там запускается 1С), и в CI на Linux.

## Проверка перед коммитом

```bash
python -m py_compile scripts/build_references.py scripts/export_sharedquery.py
python scripts/build_references.py
git status --short
```

После пересборки в `git status` не должно быть неожиданных изменений в `references/`; если они
есть — это часть коммита, а не побочный эффект. Предупреждения о качестве выгрузки в stderr —
ожидаемы; они не чинятся в этом репозитории (ни в `data/`, ни в `references/`), а передаются в
SharedQueryDesignerHRM.
