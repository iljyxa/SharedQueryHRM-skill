# SharedQuerySchemesHRM-skill

AI-скилл, наделяющий агентов знаниями о **представлениях запросов** в конфигурациях на базе
подсистемы «Зарплата и кадры» (1С:ЗУП 3.1, ЗУП КОРП, ЗКГУ и производные).

Точка входа для агента — [`SKILL.md`](SKILL.md). Справочники в `references/` по конкретным
представлениям **генерируются** из выгрузки обработки
[SharedQueryDesignerHRM](https://github.com/iljyxa/SharedQueryDesignerHRM) и вручную не
редактируются.

## Что это

Представление — описание набора данных прямо в тексте запроса (`ПОМЕСТИТЬ Представления_<Имя>`),
которое типовая процедура `ЗарплатаКадрыОбщиеНаборыДанных.ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц`
подменяет реальным запросом. В конфигурации нет справочника представлений: состав полей и
параметров зависит от версии и включённых подсистем и виден только из кода общих модулей. Скилл
даёт агенту:

- описание механизма и правила его применения в запросах, отчётах СКД и коде
  (`references/механизм-представлений.md`, `references/программный-интерфейс.md`);
- карточки всех представлений конкретной версии ЗУП: описание, параметры с типами и значениями по
  умолчанию, поля с выражениями пустых значений, заготовку текста представления, шаблон кода
  программного интерфейса (`references/<ВерсияЗУП>/<Подсистема>/<Имя>.md`).

## Структура репозитория

```text
SharedQuerySchemesHRM-skill/
├── SKILL.md                                  # точка входа агента: когда и как использовать
├── references/
│   ├── механизм-представлений.md             # статичный: синтаксис, поля, параметры, отборы, фильтр, применение
│   ├── программный-интерфейс.md              # статичный: правила заполнения шаблонов кода ПИ
│   ├── index.md                              # генерируется: версии ЗУП и таблица представлений
│   └── <ВерсияЗУП>/<Подсистема>/<Имя>.md     # генерируется: карточка представления
├── data/
│   └── <ВерсияЗУП>/<Подсистема>/<Имя>.json   # выгрузка обработки как есть, по каталогу на версию ЗУП
├── scripts/
│   ├── export_presentations.py               # запуск 1С с обработкой → data/<ВерсияЗУП>/ → references/
│   └── build_references.py                   # data/ → references/ (для CI и локальной пересборки)
└── .github/workflows/build.yml               # CI: пересборка references/ при изменении data/ или scripts/
```

## Как это устроено

1. **`scripts/export_presentations.py`** запускает 1С в режиме «Предприятие» с обработкой
   SharedQueryDesignerHRM и параметром `/C"mode=batch_client;out=<временный каталог>"`. Обработка
   собирает описания представлений **по конфигурации подключённой базы** (подсистемы,
   функциональные опции, типовые модули), пишет по одному файлу `<Подсистема>/<Имя>.json` — уже с
   текстовыми описаниями представления, полей и параметров, флагом «Основное» и шаблоном
   программного интерфейса — и завершает сеанс. Скрипт целиком заменяет этими файлами каталог
   `data/<ВерсияЗУП>/` и пересобирает `references/`.
2. **`scripts/build_references.py`** читает `data/`, проверяет файлы (валидный JSON, полный набор
   ключей формата выгрузки, совпадение имени файла и каталога с полями «Имя» и «Подсистема»,
   отсутствие дублей) и рендерит карточки `references/<ВерсияЗУП>/<Подсистема>/<Имя>.md` и
   `references/index.md`. Каталоги версий в `references/` пересоздаются целиком; статичные
   документы не трогаются.

Формат файла выгрузки описан в README обработки, раздел «Пакетный режим: выгрузка описаний в
JSON». Никаких собственных описаний, схем или метаданных репозиторий не ведёт — всё содержимое
карточек берётся из выгрузки.

### Версии ЗУП

Состав представлений и их полей меняется от версии к версии, поэтому выгрузки хранятся по
каталогам с именем версии конфигурации: `data/3.1.30.116/`, `data/3.1.38.92/` и т. д. Выгрузка
версию не содержит — она передаётся скрипту явно (`--zup-version`). Агент выбирает каталог с
наибольшей версией, не превышающей версию базы пользователя. Устаревшие версии удаляются
обычным `git rm -r data/<ВерсияЗУП>` с последующей пересборкой.

## Выгрузка из базы ЗУП

Нужны: платформа 1С на этой машине, доступ к базе ЗУП пользователем с правом открывать внешние
обработки, Python 3.10+. Внешних зависимостей у скриптов нет.

```bash
python scripts/export_presentations.py --zup-version 3.1.38.92 --infobase-path "C:\bases\zup" --username Администратор
```

Серверная база и своя копия обработки:

```bash
python scripts/export_presentations.py --zup-version 3.1.38.92 --infobase-server srv --infobase-ref zup_prod --username api --password "secret" --processing "C:\tools\КонструкторПредставленийЗарплатаКадры.epf"
```

- Если `--processing` не указан, скрипт скачивает `.epf` последнего релиза SharedQueryDesignerHRM
  во временный каталог.
- `--mode batch_client` (по умолчанию) — форма обработки открывается на экране, файлы сохраняет
  клиент 1С на этот компьютер; работает и с серверной базой. `--mode batch` — файлы пишет сервер
  1С без открытия формы; подходит для файловой базы или когда сервер на той же машине.
- `--v8path` — путь к `1cv8`, если автоопределение не сработало; `--timeout` — ожидание
  завершения 1С в секундах (по умолчанию 1800); `--no-build` — не пересобирать `references/`.
- Вывод платформы и лог `/Out` печатаются в консоль; код возврата 1 при любой ошибке.

После выгрузки проверьте `git status`: новые и изменённые файлы в `data/<ВерсияЗУП>/` и
`references/` коммитятся вместе.

## Пересборка references/ без базы

```bash
python scripts/build_references.py
```

Запускается при любой правке `data/` или скриптов; то же делает CI
(`.github/workflows/build.yml`) при пуше в `main` и коммитит результат.

## Документация механизма

`references/механизм-представлений.md` и `references/программный-интерфейс.md` написаны по
README обработки SharedQueryDesignerHRM (разделы «Механизм представлений запросов», «Код
программного интерфейса») и её модулю объекта, но адаптированы для агента, который пишет текст
запроса сам, а не пользуется формой. При существенных изменениях в документации обработки эти
файлы нужно обновить вручную.
