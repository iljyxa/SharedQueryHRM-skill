# Программный интерфейс представлений

Для части представлений типовая конфигурация предоставляет экспортные функции, которые создают
ту же временную таблицу напрямую из кода на встроенном языке, без текста представления и без
`ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц`. Это удобно, когда данные получаются в коде
(обработка, регламентное задание, сервис), а не в СКД.

У таких представлений в справочнике (`references/<ВерсияЗУП>/<Подсистема>/<Имя>.md`) стоит
«Программный интерфейс: есть» и есть раздел с **шаблоном кода** — заготовкой с плейсхолдерами
вида `<Имя>`. Шаблоны выгружены из обработки SharedQueryDesignerHRM; правила их заполнения ниже
воспроизводят логику обработки (`КодПрограммногоИнтерфейса` в модуле объекта), потому что
описания параметров шаблона в выгрузку не попадают.

Представления с программным интерфейсом (по состоянию на обработку 1.2.x): `Периоды`,
`СрезПоследних`, `СрезПервых`, `ТаблицаРегистра`, `КадровыеДанныеСотрудников`,
`КадровыеДанныеФизическихЛиц`, `РабочиеМестаСотрудников`, `СотрудникиОрганизации`,
`СтажиСотрудников`, `ТекущаяКадроваяРасстановка`, `ФактическиеОтпускаСотрудников`,
`ШтатноеРасписание`. Актуальный список — по признаку в справочнике нужной версии.

## Общие соглашения шаблона

- Переменная `МенеджерВременныхТаблиц` в шаблоне не объявляется — предполагается, что она уже
  есть в вызывающем коде (`МенеджерВременныхТаблиц = Новый МенеджерВременныхТаблиц` или
  `Запрос.МенеджерВременныхТаблиц`). Все таблицы фильтра должны быть в том же менеджере.
- Имя результирующей временной таблицы задаётся в шаблоне явно (`"ВТПериоды"`,
  `"ВТСтажиСотрудников"`, `"ВТ<ИмяРегистра>"`) либо определяется типовой функцией; дальше к ней
  обращаются обычным запросом с тем же менеджером временных таблиц.
- Шаблон — заготовка: параметры запроса вида `&НачалоПериода` из значений по умолчанию нужно
  заменить реальными значениями или переменными, а плейсхолдеры, которые нельзя вычислить из
  описания представления (`<ИзмеренияФильтра>`), заполняются вручную.

## Плейсхолдеры

| Плейсхолдер | Чем заменить |
|---|---|
| `<Фильтр>` | Имя временной таблицы фильтра из менеджера временных таблиц. В шаблоне уже стоит в кавычках (`"<Фильтр>"`), подставляется только имя: `"ВТФильтр"`. Состав полей таблицы — см. «Таблица фильтра» в `references/механизм-представлений.md` и имена полей, которые ожидает типовая функция в самом шаблоне (`ИмяПоляСотрудник = "Сотрудник"` и т. п.). |
| `<ИмяРегистра>` | Имя периодического регистра сведений — источника данных (`ГрафикРаботыСотрудников`, `КадроваяИсторияСотрудников`, …). Встречается несколько раз, в том числе в имени результирующей таблицы `"ВТ<ИмяРегистра>"`. |
| `<ТолькоРазрешенные>` | `Истина` или `Ложь` — учитывать ли ограничения доступа на уровне записей (аналог параметра `ТолькоРазрешенные` представления). |
| `<КадровыеДанные>` | Имена нужных полей представления: строкой через запятую без пробелов — `"Период,Сотрудник,ФизическоеЛицо"`; если полей много — массив строк, объявленный перед вызовом (`КадровыеДанные = Новый Массив; КадровыеДанные.Добавить("Период"); …`), и в плейсхолдер подставляется имя переменной. Имена — только из таблицы «Поля» представления. |
| `<Отборы>` | Строка шаблона целиком заменяется вызовами по одному на отбор: `ЗарплатаКадрыОбщиеНаборыДанных.ДобавитьВКоллекциюОтбор(ПараметрыПостроения.Отборы, "ИмяПоля", "=", Значение);` — имя поля представления, вид сравнения строкой (`"="`, `"<>"`, `">"`, `">="`, `"<"`, `"<="`, `"В"`, `"В ИЕРАРХИИ"`), значение — выражение встроенного языка (ссылка, переменная, литерал). Если отборов нет — строку удалить. |
| `<ПсевдонимыПолейСКД>` | Строка шаблона заменяется на `ПараметрыПостроения.СоответствиеПсевдонимовПолейСКД.Вставить("Поле", "Псевдоним");` по одной на переименование. Если переименований нет — строку удалить. |
| `<ИзмеренияФильтра>` | Заполняется вручную: описание измерений регистра, по которым таблица фильтра соединяется с регистром, — в форме, которую ожидает `ЗарплатаКадрыОбщиеНаборыДанных.ОписаниеФильтраДляСоздатьВТИмяРегистра` в конфигурации пользователя (обычно строка с именами измерений через запятую, совпадающими с колонками таблицы фильтра). Сверяйся с сигнатурой функции в конфигурации. |
| `<ИмяПараметра>` — любой другой | Значение одноимённого параметра представления (таблица «Параметры»), записанное литералом встроенного языка: булево — `Истина`/`Ложь`, число — как есть, строка — в кавычках (если плейсхолдер в шаблоне уже обёрнут в кавычки, как `"<Периодичность>"`, подставляется только текст), дата — `Дата(2025, 1, 1)` или переменная. Значения по умолчанию вида `&НачалоПериода` — это параметры запроса, в коде их заменяют переменной с датой. |

Исключение из правила «плейсхолдер = одноимённый параметр»: у `ШтатноеРасписание` плейсхолдеры
`<ДополнитьОписаниемНачислений>` и `<ПолноеОписаниеНачислений>` оба заполняются значением
параметра представления `ВключатьНачисления`.

## Необязательные параметры, которые не нужны

Если необязательный параметр не задаётся, его строка из шаблона убирается так, чтобы код остался
корректным:

- строка — самостоятельный оператор (`ПараметрыПостроения.ВключаяЗакрытые = <ВключаяЗакрытые>;`):
  удаляется целиком;
- строка — непоследний аргумент вызова (`<Периодичность>,`): от неё остаётся только запятая, чтобы
  сохранить позицию аргумента — получается допустимая конструкция `Метод(Первый, , Третий)`;
- строка — последний аргумент (`<ИспользоватьКонецПериода>);`): строка удаляется, а `);`
  переносится на место запятой предыдущего аргумента.

Обязательные плейсхолдеры заполняются всегда: `<Фильтр>` и `<ИмяРегистра>` везде, где они есть в
шаблоне, `<КадровыеДанные>` у `КадровыеДанныеСотрудников` и `КадровыеДанныеФизическихЛиц`, `<Дата>` у
`ТекущаяКадроваяРасстановка`, `<НачалоИнтервала>`/`<ОкончаниеИнтервала>` у `Периоды`,
`<ТолькоРазрешенные>` — везде (у него всегда есть значение, по умолчанию `Ложь`).

## Пример: заполнение шаблона `Периоды`

Шаблон из справочника:

```bsl
ЗарплатаКадрыОбщиеНаборыДанных.СоздатьВТПериоды(
	МенеджерВременныхТаблиц,
	<НачалоИнтервала>,
	<ОкончаниеИнтервала>,
	"<Периодичность>",
	"ВТПериоды",
	<ИспользоватьКонецПериода>);
```

Результат для сетки месяцев за год с началом периода:

```bsl
МенеджерВременныхТаблиц = Новый МенеджерВременныхТаблиц;

ЗарплатаКадрыОбщиеНаборыДанных.СоздатьВТПериоды(
	МенеджерВременныхТаблиц,
	НачалоГода(ТекущаяДатаСеанса()),
	КонецГода(ТекущаяДатаСеанса()),
	"МЕСЯЦ",
	"ВТПериоды");
```

`ИспользоватьКонецПериода` не понадобился — строка последнего аргумента убрана, `);` перенесено.

## Пример: заполнение шаблона `СрезПоследних`

```bsl
МенеджерВременныхТаблиц = Новый МенеджерВременныхТаблиц;

// Таблица фильтра: измерение регистра + Период.
Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = МенеджерВременныхТаблиц;
Запрос.Текст =
	"ВЫБРАТЬ
	|	&Период КАК Период,
	|	Сотрудники.Ссылка КАК Сотрудник
	|ПОМЕСТИТЬ ВТФильтр
	|ИЗ
	|	Справочник.Сотрудники КАК Сотрудники";
Запрос.УстановитьПараметр("Период", ТекущаяДатаСеанса());
Запрос.Выполнить();

ОписаниеФильтра = ЗарплатаКадрыОбщиеНаборыДанных.ОписаниеФильтраДляСоздатьВТИмяРегистра(
	"ВТФильтр", "Сотрудник");

ПараметрыПостроения = ЗарплатаКадрыОбщиеНаборыДанных.ПараметрыПостроенияДляСоздатьВТИмяРегистраСрез();
ПараметрыПостроения.ФормироватьСПериодичностьДень = Истина;
ЗарплатаКадрыОбщиеНаборыДанных.ДобавитьВКоллекциюОтбор(ПараметрыПостроения.Отборы, "ГрафикРаботы", "=", ГрафикРаботы);

ЗарплатаКадрыОбщиеНаборыДанных.СоздатьВТИмяРегистраСрезПоследних(
	"ГрафикРаботыСотрудников",
	МенеджерВременныхТаблиц,
	Ложь,
	ОписаниеФильтра,
	ПараметрыПостроения,
	"ВТГрафикРаботыСотрудников");
```

Здесь `<ИзмеренияФильтра>` заполнено строкой `"Сотрудник"` — проверь форму этого аргумента по
сигнатуре `ОписаниеФильтраДляСоздатьВТИмяРегистра` в конфигурации пользователя; строка
`<ПсевдонимыПолейСКД>` удалена, `<Отборы>` заменена одним вызовом `ДобавитьВКоллекциюОтбор`.

## Когда что выбирать

- **Отчёт на СКД, печатная форма, набор данных** — текст представления в запросе набора данных +
  `ЗарплатаКадрыОтчеты.ПриКомпоновкеРезультатаВТабличныйДокумент`.
- **Данные нужны в коде** (обработка, обмен, регламентное задание) — программный интерфейс, если
  он есть у представления; иначе текст представления в объекте `Запрос` с
  `ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц`.
- Оба способа дают одну и ту же временную таблицу; текст представления при обновлении конфигурации
  остаётся актуальным автоматически, а сигнатуры функций программного интерфейса могут меняться.
