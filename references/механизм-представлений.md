# Механизм представлений запросов ЗУП

Справочник для агента: что такое представление, как его записать в тексте запроса, чем оно
управляется и как заставить конфигурацию его выполнить. Написан по документации обработки
[SharedQueryDesignerHRM](https://github.com/iljyxa/SharedQueryDesignerHRM) (раздел «Механизм
представлений запросов») и коду типовой конфигурации; состав полей и параметров конкретных
представлений — в `references/<ВерсияЗУП>/<Подсистема>/<Имя>.md`.

## Идея

Представление — это описание набора данных, которое пишется прямо в тексте запроса в виде
запроса помещения во временную таблицу с именем `Представления_<Имя>`. Разработчик перечисляет
нужные поля и параметры, а получение данных происходит «под капотом»: перед выполнением типовая
процедура `ЗарплатаКадрыОбщиеНаборыДанных.ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц`
находит такие описания и заменяет их на реальные запросы к регистрам и справочникам, используя
типовые алгоритмы подсистемы (кадровые данные на дату с учётом всех кадровых событий, срезы
регистров, штатное расписание, учёт времени и т. д.).

По сути это виртуальные таблицы уровня конфигурации: как виртуальная таблица регистра скрывает
алгоритм расчёта остатков, так представление скрывает алгоритм получения, например, кадровых
данных сотрудников.

Представления есть во всех конфигурациях на базе подсистемы «Зарплата и кадры» (ЗУП 3.1
базовая/ПРОФ/КОРП, ЗКГУ 3.1 и производные) начиная с общего модуля
`ЗарплатаКадрыОбщиеНаборыДанных`. Часть представлений доступна только при наличии подсистемы
или функциональной опции (обычно в КОРП) — это видно по тому, есть ли файл представления в
выгрузке нужной версии.

## Как устроена замена

Единого реестра представлений в конфигурации нет — это **диспетчеризация по имени** в цепочке
общих модулей. Головная функция
`ЗарплатаКадрыОбщиеНаборыДанных.ПолучитьЗапросПоПредставлению(ТекстЗапроса, СоответствиеПараметров)`
передаёт описание в `ЗарплатаКадрыОбщиеНаборыДанныхРасширенный` (штатное расписание, кадровая
расстановка, отпуска, плановые начисления и удержания, стажи, статьи финансирования, бухучёт
зарплаты), далее по цепочке: `УчетРабочегоВремениРасширенный.ЗапросПоПредставлению` (учёт
времени, плановое время) → модули прикладных подсистем (аттестации, медицина, бюджетные
учреждения, охрана труда, кадровое планирование, подбор персонала, кадровый резерв, медосмотры,
организационная структура — каждый вызывается только при наличии подсистемы) → в конце
`ЗарплатаКадрыОбщиеНаборыДанныхБазовый` (периоды, регистры, кадровые данные, рабочие места,
сотрудники организации, отработанное время, НДФЛ). Модуль, распознавший имя, возвращает готовый
объект `Запрос`; если имя никто не распознал или представление недоступно по функциональной
опции — `Неопределено`.

Процедура `ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц(ТекстЗапроса, Приемник)`:

1. Разбивает пакет по `;` и в каждом запросе ищет `ПОМЕСТИТЬ`, за которым следует
   `Представления_` — это описание представления.
2. Разбирает описание: имя и источник данных — из имени временной таблицы, таблица фильтра — из
   секции `ИЗ`, поля — имена после `КАК` в секции `ВЫБРАТЬ`, параметры — пары `"Имя" = Значение`
   из секции `ГДЕ` (кавычки снимаются с обеих частей). Значение параметра — просто строка из
   текста; как её понимать (`ИСТИНА`, `"МЕСЯЦ"`, `&НачалоПериода`, `НАЧАЛОПЕРИОДА(&Дата, МЕСЯЦ)`),
   решает построитель конкретного представления. Построитель забирает только известные ему
   параметры, остальные молча игнорируются.
3. Подставляет полученный текст вместо описания. Имя временной таблицы переписывается без
   подчёркивания: `Представления_КадровыеДанныеСотрудников` → `ПредставленияКадровыеДанныеСотрудников`,
   и во всём пакете `Представления_` заменяется на `Представления` — обращения к таблице из других
   запросов пакета тоже переименовываются. Замена рекурсивна: построенный текст сам может
   содержать представления.
4. Переносит параметры запроса, которые создал построитель (например, `&Период` внутри реального
   текста), в приёмник — объект `Запрос`, динамический список или схему компоновки данных.

Если построитель вернул `Неопределено`, описание **остаётся в тексте как есть** (с тем же
переименованием). Ошибки не возникает: запрос выполнится, но временная таблица будет содержать
пустые значения из выражений-заглушек, а не реальные данные. Поэтому неверное имя представления
или недоступная подсистема проявляются «тихо» — пустыми данными.

## Синтаксис представления в тексте запроса

Представление — отдельный запрос пакета, помещающий результат во временную таблицу с именем,
начинающимся на `Представления_`:

```bsl
ВЫБРАТЬ
	ДАТАВРЕМЯ(1, 1, 1) КАК Период,
	ЗНАЧЕНИЕ(Справочник.Сотрудники.ПустаяСсылка) КАК Сотрудник,
	"" КАК ИОФамилия,
	0 КАК ОбщийСтажЛет
ПОМЕСТИТЬ Представления_КадровыеДанныеСотрудников
ИЗ
	ВТФильтр КАК ВТФильтр
ГДЕ
	"ТолькоРазрешенные" = ЛОЖЬ
	И "ФормироватьСПериодичностьДень" = ИСТИНА
```

| Часть | Назначение |
|---|---|
| `ВЫБРАТЬ … КАК <Имя>` | Поля, которые должны попасть в результат. Слева от `КАК` — типизированное пустое значение из колонки «Выражение» справочника (см. [Поля](#поля)). |
| `ПОМЕСТИТЬ Представления_<Имя>[_<ИсточникДанных>][_<Уточнение>]` | Имя представления и, при необходимости, имя регистра-источника и постфикс (см. [Источник данных и уточнение](#источник-данных-и-уточнение)). Дальше в пакете к результату обращаются как к обычной временной таблице `Представления_<Имя>…` (в исполняемом тексте подчёркивание исчезнет — механизм переименует и таблицу, и обращения к ней). |
| `ИЗ <ТаблицаФильтра> КАК <ТаблицаФильтра>` | Необязательная (для части представлений — обязательная) таблица фильтра — временная таблица того же пакета (см. [Таблица фильтра](#таблица-фильтра)). |
| `ГДЕ "<Параметр>" = <Значение> И …` | Параметры представления и отборы. Имя параметра — строковый литерал в кавычках (см. [Параметры](#параметры) и [Отборы](#отборы)). |

Такая запись выглядит непривычно, но она синтаксически корректна: конструктор запроса и схема
компоновки данных её принимают, а типовой механизм подменяет её реальным текстом до выполнения.
Текст представления должен содержать хотя бы одно поле, иначе запрос синтаксически некорректен.

## Поля

В секции `ВЫБРАТЬ` перечисляются поля представления, нужные в результате. Слева от `КАК` пишется
не реальное выражение, а **пустое значение нужного типа**:

| Тип поля | Выражение |
|---|---|
| Ссылка | `ЗНАЧЕНИЕ(Справочник.Сотрудники.ПустаяСсылка)`, `ЗНАЧЕНИЕ(Перечисление.ВидыЗанятости.ПустаяСсылка)` |
| Дата | `ДАТАВРЕМЯ(1, 1, 1)` |
| Число | `0` или `ВЫРАЗИТЬ(0 КАК ЧИСЛО(15, 2))` |
| Строка | `""` или `ВЫРАЗИТЬ("" КАК СТРОКА(150))` |
| Булево | `ЛОЖЬ` |
| Составной или неизвестный тип | `НЕОПРЕДЕЛЕНО` |

Тип нужен только для того, чтобы запрос был корректен **до** замены: по этим выражениям СКД и
конструктор запроса определяют типы полей временной таблицы. Сам механизм выражения игнорирует —
построителю передаются только имена полей (первое слово после последнего `КАК` в строке), а
реальные типы определяет он.

**Правила для агента:**

- Имя после `КАК` должно **буквально** совпадать с именем поля из таблицы «Поля» справочника
  представления. Полей, которых там нет, не существует — не придумывай.
- Выражение слева от `КАК` бери из колонки «Выражение» той же таблицы — оно уже подобрано по
  типу поля.
- Для представлений на основе регистров (`СрезПоследних`, `СрезПервых`, `ТаблицаРегистра`) состав
  полей — измерения, ресурсы и реквизиты выбранного регистра сведений; выражения подбирай по
  таблице выше.
- Часть полей построители добавляют в результат всегда, даже если они не перечислены: для
  кадровых данных это `Сотрудник`, `ФизическоеЛицо` и `Период` (плюс поля, по которым заданы
  отборы), для `НачисленныеДоходыНДФЛ` — фиксированный набор, для представлений на основе
  регистров — измерения, ресурсы и реквизиты регистра. Перечислять их всё равно стоит — иначе
  СКД не увидит их до замены.

## Параметры

Параметры перечисляются в секции `ГДЕ` в виде условий `"<ИмяПараметра>" = <Значение>`,
соединённых через `И`. Значение может быть:

- литералом — строкой в кавычках (`"МЕСЯЦ"`), числом (`10`), булевым (`ИСТИНА` / `ЛОЖЬ`), датой
  (`ДАТАВРЕМЯ(2025, 1, 1, 0, 0, 0)`);
- выражением языка запросов — чаще всего параметром запроса `&НачалоПериода` или функцией вида
  `НАЧАЛОПЕРИОДА(&ДатаНачала, МЕСЯЦ)`. Значения параметров запроса устанавливаются обычным образом
  в объекте `Запрос` или в настройках СКД.

Механизм не различает строковые и, например, числовые или булевы параметры — он подставляет
текст как есть. Поэтому в справочнике у каждого параметра указано значение по умолчанию уже в
записи языка запросов (`"МЕСЯЦ"` — строка в кавычках, `ИСТИНА` — булево, `&НачалоПериода` —
выражение без кавычек); пиши так же.

Общие параметры большинства представлений:

- `ТолькоРазрешенные` — учитывать ограничения доступа на уровне записей. Построители формируют
  запросы с `ВЫБРАТЬ РАЗРЕШЕННЫЕ`, и только если параметр не равен строго `ИСТИНА`, слово
  `РАЗРЕШЕННЫЕ` убирается. По умолчанию `ЛОЖЬ`.
- Параметры периода — у каждого представления свои: `НачалоПериода`/`ОкончаниеПериода`
  (сотрудники организации, отработанное время), `НачалоИнтервала`/`ОкончаниеИнтервала` (периоды),
  `ДатаНачала`/`ДатаОкончания` (учёт времени), `ДатаАктуальности` (штатное расписание), `Дата`
  (кадровая расстановка). Обязательные параметры по умолчанию заполняются одноимёнными
  параметрами запроса (`&НачалоПериода` и т. д.) — их значения нужно установить в `Запрос` или СКД.
- Параметры с префиксом `ПараметрыПостроения_` передаются в структуру параметров построения
  типовой функции. Это фиксированный набор имён, а не произвольные свойства структуры:
  `ПараметрыПостроения_ФормироватьСПериодичностьДень` (представления на основе регистров) и
  `ПараметрыПостроения_ВключатьЗаписиНаНачалоПериода` (только `ТаблицаРегистра`); какие из них
  есть у представления — видно в его таблице параметров.
- `ПсевдонимыПолейСКД` — строка вида `"Поле1 КАК Псевдоним1, Поле2 КАК Псевдоним2"`,
  переименование полей результата. Читается только представлениями на основе регистров
  (`СрезПоследних`, `СрезПервых`, `ТаблицаРегистра`).

**Правила для агента:**

- Обязательные параметры (колонка «Обязателен» = Да) включай всегда.
- Необязательные параметры, не указанные в тексте, получают значения по умолчанию внутри
  построителя (например, у `Периоды` это `Периодичность = МЕСЯЦ`). Указывай их только когда нужно
  другое значение.
- Параметры, которых построитель не знает, молча игнорируются — опечатка в имени параметра не
  даст ошибки, а просто не сработает. Сверяй имена со справочником.

## Отборы

Для части представлений можно указать отборы по полям. Каждый элемент отбора записывается
**тремя параметрами** с общим номером:

```bsl
ГДЕ
	"ЛевоеЗначение1" = "Подразделение"
	И "ВидСравнения1" = "="
	И "ПравоеЗначение1" = &Подразделение
	И "ЛевоеЗначение2" = "ВидЗанятости"
	И "ВидСравнения2" = "<>"
	И "ПравоеЗначение2" = ЗНАЧЕНИЕ(Перечисление.ВидыЗанятости.ВнутреннееСовместительство)
```

- `ЛевоеЗначениеN` — имя поля представления;
- `ВидСравненияN` — условие языка запросов: `=`, `<>`, `>`, `>=`, `<`, `<=`, `В`, `В ИЕРАРХИИ`.
  Механизм подставляет условие в текст как есть, не проверяя по списку;
- `ПравоеЗначениеN` — значение или выражение. Значение вида `ВЫЧИСЛИТЬ(…)` вычисляется построителем
  в безопасном режиме, остальные подставляются как есть.

Номер `N` различает тройки: без разных суффиксов несколько отборов перезаписали бы друг друга.
Порядок отборов значения не имеет.

Отборы понимают ровно пять представлений — те, чьи построители вызывают
`КоллекцияОтборПоПараметрам`: `КадровыеДанныеСотрудников`, `КадровыеДанныеФизическихЛиц`,
`СрезПоследних`, `СрезПервых`, `ТаблицаРегистра` (в справочнике у них «Отборы по полям:
поддерживаются»). У остальных тройки отборов будут проигнорированы — ограничивай выборку
таблицей фильтра или условиями в следующем запросе пакета.

## Таблица фильтра

Многие представления получают данные не по всей базе, а по списку объектов и периодов,
который передаётся временной таблицей. Её имя указывается в секции `ИЗ`:

```bsl
ИЗ
	ВТФильтр КАК ВТФильтр
```

Таблица фильтра должна быть создана **раньше в том же пакете** (или в менеджере временных
таблиц). Механизм берёт первую таблицу из секции `ИЗ`, отбирает по ней записи, а по её полям
периода определяет даты, на которые нужны данные. Состав полей зависит от представления:

- **Кадровые данные** (`КадровыеДанныеСотрудников`, `КадровыеДанныеФизическихЛиц`,
  `СотрудникиОрганизации` и др.): поле сотрудника (`Сотрудник` или `ФизическоеЛицо`) и `Период`.
- **Представления за период** (`ФактическиеОтпускаСотрудников`, `РабочиеМестаСотрудников` и др.):
  `Сотрудник` и `НачалоПериода`/`ОкончаниеПериода`. Точный состав — в описании представления и в
  шаблоне его программного интерфейса: там видно, какие имена полей ожидает типовая функция.
- **Представления на основе регистров** (`СрезПоследних`, `СрезПервых`, `ТаблицаРегистра`): поля
  периода — `Период` либо `ДатаНачала` и `ДатаОкончания` (для `ТаблицаРегистра` —
  `ДатаНачала`/`ДатаОкончания`); **все остальные колонки считаются измерениями** и должны
  называться так же, как измерения регистра, — по ним накладывается отбор.

Если нужных полей в таблице нет, внятной ошибки не будет: отбор по отсутствующему измерению не
сформируется или соединение окажется неверным, и результат будет неполным.

В справочнике у каждого представления указано: таблица фильтра не используется, не обязательна
(без неё будут получены все записи) или обязательна; если типовой механизм ожидает таблицу с
конкретным именем (например, `ВТОсновныеСотрудники`), это имя указано — используй его.

Типовой пример таблицы фильтра для кадровых данных:

```bsl
ВЫБРАТЬ РАЗРЕШЕННЫЕ
	&Период КАК Период,
	Сотрудники.Ссылка КАК Сотрудник
ПОМЕСТИТЬ ВТФильтр
ИЗ
	Справочник.Сотрудники КАК Сотрудники
ГДЕ
	Сотрудники.ГоловнаяОрганизация = &Организация
;
```

## Источник данных и уточнение

Три базовых представления — `СрезПоследних`, `СрезПервых` и `ТаблицаРегистра` — универсальны:
они получают данные любого **периодического регистра сведений**, имя которого указывается в
имени временной таблицы через подчёркивание:

```bsl
ПОМЕСТИТЬ Представления_СрезПоследних_ГрафикРаботыСотрудников
```

Имена регистров могут содержать подчёркивания (префиксы расширений) — механизм это учитывает.

**Уточнение** — произвольный постфикс после имени представления и источника данных:

```bsl
ПОМЕСТИТЬ Представления_КадровыеДанныеСотрудников_НаНачалоПериода
ПОМЕСТИТЬ Представления_КадровыеДанныеСотрудников_НаКонецПериода
```

Он нужен, когда в одном пакете требуется несколько одинаковых представлений с разными параметрами
или фильтрами: постфикс делает имена временных таблиц уникальными.

## Как применить представление

Представление можно вставить в любой текст запроса — объекта `Запрос` или набора данных схемы
компоновки данных. Само по себе оно не выполняется: текст обязательно должен пройти через замену.

### Произвольный запрос в коде

Перед выполнением текст передаётся в
`ЗарплатаКадрыОбщиеНаборыДанных.ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц`. Первый
параметр — текст пакета, он изменяется на месте (передаётся по ссылке); второй — приёмник
параметров запроса, которые создают построители: объект `Запрос`, динамический список или схема
компоновки данных. Условия:

- у запроса должен быть `МенеджерВременныхТаблиц` — представление помещается во временную таблицу;
- описание представления должно стоять в пакете раньше запросов, которые обращаются к
  `Представления_…`;
- таблица фильтра, если она используется, — раньше описания представления.

```bsl
Запрос = Новый Запрос;
Запрос.МенеджерВременныхТаблиц = Новый МенеджерВременныхТаблиц;
Запрос.Текст =
	"ВЫБРАТЬ РАЗРЕШЕННЫЕ
	|	&Период КАК Период,
	|	Сотрудники.Ссылка КАК Сотрудник
	|ПОМЕСТИТЬ ВТФильтр
	|ИЗ
	|	Справочник.Сотрудники КАК Сотрудники
	|;
	|
	|////////////////////////////////////////////////////////////////////////////////
	|ВЫБРАТЬ
	|	ДАТАВРЕМЯ(1, 1, 1) КАК Период,
	|	ЗНАЧЕНИЕ(Справочник.Сотрудники.ПустаяСсылка) КАК Сотрудник,
	|	"""" КАК ИОФамилия,
	|	0 КАК ОбщийСтажЛет
	|ПОМЕСТИТЬ Представления_КадровыеДанныеСотрудников
	|ИЗ
	|	ВТФильтр КАК ВТФильтр
	|ГДЕ
	|	""ТолькоРазрешенные"" = ИСТИНА
	|;
	|
	|////////////////////////////////////////////////////////////////////////////////
	|ВЫБРАТЬ
	|	КадровыеДанные.Сотрудник КАК Сотрудник,
	|	КадровыеДанные.ИОФамилия КАК ИОФамилия,
	|	КадровыеДанные.ОбщийСтажЛет КАК ОбщийСтажЛет
	|ИЗ
	|	Представления_КадровыеДанныеСотрудников КАК КадровыеДанные";

Запрос.УстановитьПараметр("Период", ТекущаяДатаСеанса());

ЗарплатаКадрыОбщиеНаборыДанных.ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц(Запрос.Текст, Запрос);
Результат = Запрос.Выполнить();
```

В строковом литерале кавычки удваиваются: `"ТолькоРазрешенные"` в тексте запроса записывается
как `""ТолькоРазрешенные""`, пустая строка `""` — как `""""`.

### Отчёты на СКД и печатные формы

Основное применение представлений. Чтобы отчёт с представлениями сформировался, в модуле объекта
отчёта в обработчике `ПриКомпоновкеРезультата` вызывается
`ЗарплатаКадрыОтчеты.ПриКомпоновкеРезультатаВТабличныйДокумент`: процедура отключает
стандартную обработку и перед компоновкой проходит по всем наборам данных схемы — наборам-запросам,
в тексте которых есть `Представления_`, и рекурсивно по наборам-объединениям, — заменяя
представления и перенося параметры в схему. Менеджер временных таблиц при компоновке создаёт
платформа.

```bsl
Процедура ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)
	ЗарплатаКадрыОтчеты.ПриКомпоновкеРезультатаВТабличныйДокумент(ЭтотОбъект, ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка);
КонецПроцедуры
```

Текст представления вместе с таблицей фильтра и итоговым запросом помещается в текст запроса
набора данных СКД как обычный пакет. Параметры вида `&Период`, `&НачалоПериода` объявляются
параметрами схемы и заполняются в настройках отчёта; параметры, которые создают сами построители,
механизм добавляет в схему при замене. Примеры стандартных и нестандартных вариантов
формирования есть в типовых отчётах и печатных формах конфигурации.

## Программный интерфейс вместо текста

Для части представлений типовая конфигурация предоставляет экспортные функции, которые создают ту
же временную таблицу напрямую из кода, без текста представления
(`КадровыйУчет.СоздатьВТКадровыеДанныеСотрудников`, `ЗарплатаКадрыОбщиеНаборыДанных.СоздатьВТПериоды`
и др.). Это удобно, когда данные получаются в коде, а не в СКД. Шаблоны такого кода есть в
справочнике представлений (раздел «Программный интерфейс»), правила их заполнения — в
`references/программный-интерфейс.md`.

Шаблон показывает одну форму — временную таблицу по таблице фильтра. Помимо неё в конфигурации у
тех же представлений есть ТЗ-функции (возвращают `ТаблицуЗначений`; например
`КадровыйУчет.КадровыеДанныеСотрудников`), упрощённая форма по массиву ссылок `СоздатьНаДатуВТ*`
(таблицу фильтра строит сама) и запрос-функции `ЗапросВТ*` (возвращают объект `Запрос`). Все формы
одного представления используют один набор полей — таблицу «Поля» его карточки; параметр
`КадровыеДанные` в любой форме принимает имена этих полей через запятую. Соответствие «функция →
представление» — в `SKILL.md`, описание форм и пример — в `references/программный-интерфейс.md`.

## Ограничения и типичные ошибки

- Механизм не сообщает об ошибках в описании представления: неизвестное представление остаётся
  в тексте с пустыми значениями полей, неизвестные параметры игнорируются, неполная таблица
  фильтра даёт неполный результат. Если результат пустой — проверь имя представления, имена
  параметров и состав таблицы фильтра.
- Набор представлений и их полей зависит от версии конфигурации и включённых подсистем: если в
  выгрузке нужной версии представления нет, в этой базе его, скорее всего, нет.
- Представления, добавленные расширениями, в справочнике не описаны, но механизм их
  поддерживает — синтаксис тот же.
- Совместимость выбранных полей и параметров с логикой представления проверяет только типовой
  механизм при замене; для отладки полезно посмотреть исполняемый текст — его показывает
  обработка SharedQueryDesignerHRM (закладка «Исполняемый запрос») или вызов
  `ЗаменитьЗапросыКПредставлениямВиртуальныхТаблиц` с последующим просмотром `Запрос.Текст`.
